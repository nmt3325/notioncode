# 共有 MCP と並列スレッド実行（0.6.0）

0.5.x はプロジェクトごとに Notion 接続と MCP サーバーを用意し、1 つのプロジェクトで進行できるターンは 1 つでした。0.6.0 は **接続を 1 つに固定**し、実行のたびに環境・スレッド・ターンを指定します。複数の AI が同じ MCP を使って同時に別のファイルを編集できます。

```text
Notion AI (スレッド A) ┐
Notion AI (スレッド B) ┼→ 共有 /mcp（1 接続）→ 共有デーモン → スレッドごとの Bun worker → OpenCode native tools
Notion AI (スレッド C) ┘
```

## 接続は 1 つ、指定は実行時

すべての native ツールと制御ツールが、次の 3 つの ID を **必須** で受け取ります。native 側の入力スキーマは `arguments` にそのまま入れ替えなしで入ります。

```json
{
  "env_id": "env-…",
  "thread_id": "<会話 ID>",
  "turn_id": "<そのターンの ID>",
  "arguments": { "filePath": "/abs/path", "oldString": "…", "newString": "…" }
}
```

- `env_id`：編集対象のワークスペース（プロジェクト）。起動したプラグインが自分のルートを登録し、`cwd` と native のパス検査に使われます。
- `thread_id`：会話 = 1 AI。スレッドごとに専用の native worker と state を持ちます。
- `turn_id`：そのターン。毎ターン新しい ID を送ります。

プラグインは毎ターン、プロンプトに現在の scope と環境ルートを明示します。ID が欠けている・別スレッドのジョブを指しているリクエストは実行されません。接続名にプロジェクトのパスは含めません（公開 URL のハッシュのみ）。

## 並列実行と分離

- **1 スレッド = 1 AI = 1 進行中ターン。** 別スレッドは同時に走ります。同じスレッドへの別ターンの同時開始と、他の起動からの割り込みは拒否します。
- ジョブ一覧・結果待ち・キャンセル・権限応答は、**そのスレッドのそのターンのジョブだけ**が対象です。他スレッドのジョブ ID を渡しても拒否されます。
- 表示（ツールカード）とイベント履歴も scope 付きで振り分けます。同じ job ID が別スレッドで衝突しても混ざりません。
- ターン終了時は **そのターンのジョブだけ** をキャンセルします。他スレッドは動き続けます。終了後に届いた遅延リクエストは実行されず、そのターンの保存済み結果だけ参照できます。
- キャンセルが 5 秒で確認できない場合は、その worker だけを隔離して停止します。
- 会話ごとに Notion クライアントと状態ファイルを分け、ジャーナルはセッション単位のファイルとロックに分割しました。別プロセスの別セッションでも書き込みは失われません。同じセッションを二重に進めることはロックで拒否します。

### 中断・喪失時の回復

- 停止（Esc）は、そのスレッドの Notion 推論の中断と、そのターンの native ジョブのキャンセルだけを行います。
- ターン境界の応答が失われた場合、そのスレッドの次の開始時に **fence**（残っている進行中ターンの終了）を自動で行ってから開始します。他スレッドには触れません。
- 表示履歴が溢れた場合は、後続イベントで置き換わった途中経過だけを落とし、履歴の欠落として報告します。**他スレッドの会話を中断しません。** 実行を再送することはありません。
- 応答が不明になったターンは自動再送しません。

## 制御経路と公開範囲

- 公開するのは `/mcp` だけです。実行用 bearer とは **別の** 非公開 bearer を持つ `/control` は 127.0.0.1 のみで待ち受け、プラグインの登録・ターン境界・イベント取得に使います。制御用の資格情報は AI のプロンプトに入りません。
- 資格情報は state ディレクトリ（0700 / 0600）に保存し、worker の環境変数には渡しません。`/healthz` には health・モード・バージョンのみを返します。
- 共有 bearer は **マルチテナントの隔離ではありません**。scope は「正しい相手に振り分ける」ための境界で、悪意ある利用者からの隔離や OS レベルのサンドボックスではありません。全許可の bash は OS ユーザー権限で動きます。信頼できる環境・専用コンテナで使ってください。

## 上限と寿命

| 項目 | 既定 |
| --- | --- |
| 同時スレッド数 | 32 |
| 同時実行ジョブ数（全体） | 32 |
| 環境数 / 起動数 | 各 128 |
| 起動のリース | 60 秒（200ms 間隔のポーリングで更新） |
| 待機中スレッドの回収 | 15 分（保存済みターン ID の再利用拒否は維持） |
| デーモンの自動終了 | 起動が 0 になってから 60 秒 |
| イベント履歴 | 2048 件 / 8MiB、1 ページ 128 件 |

強制終了でロックが残った場合は、該当 OpenCode が動いていないことを確認し、エラーに示された lock だけを削除してください。ロックは自動で奪いません。

## 0.5.x からの移行

1. 起動中の OpenCode をすべて終了します。
2. 0.6.0 を導入し、**同じ公開 URL・同じポート・同じ state ディレクトリ**で各プロジェクトを起動します。URL やポートをプロジェクトごとに分ける必要はありません。
3. 古いプロジェクト専用接続は自動では消しません。使い続ける場合はその接続を明示的に選び直してください。プラグインは他の接続を乗っ取らず、権限も変更せず、プロジェクト専用の代替接続も作りません。
4. 会話状態（`~/.local/state/opencode-notion`）は削除しないでください。単一ファイルの旧ジャーナルはそのまま読み込み、セッション単位の分割形式へ移行します。

## 対象外

- **同じファイルへの同時編集の調停は行いません。** 別スレッドが同じファイルを書けば、後の書き込みが優先されます。スレッドごとに担当ファイルを分けてください。
- Notion 側の会話・全履歴の同期や取り込み、ワークスペースの自動作成・ローテーションは行いません。
- 添付は未対応エラーになります（黙って破棄しません）。
